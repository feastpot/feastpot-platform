IMPLEMENTATION
════════════════════════════════════════════════════════

Based on what the audit reveals, the minimum configuration needed is:

STEP 1 — Identify required Content SIDs
The WhatsApp provider needs a Content SID for each notification
template that sends via WhatsApp. Typically these are:
  order_confirmation
  order_accepted
  order_dispatched
  delivery_confirmed

In Meta Business Manager (business.facebook.com):
1. Go to WhatsApp → Message Templates
2. For each template, find the Content SID (format: HXxx...)
3. Add to Replit deployment secrets:

  WA_CONTENT_SID_ORDER_CONFIRMATION = HXxx...
  WA_CONTENT_SID_ORDER_ACCEPTED     = HXxx...
  WA_CONTENT_SID_ORDER_DISPATCHED   = HXxx...
  WA_CONTENT_SID_DELIVERY_CONFIRMED = HXxx...

STEP 2 — Wire Content SIDs in the provider
File: apps/api/src/modules/notifications/providers/whatsapp.provider.ts

If the provider does not already read these from env, add a mapping:

private readonly contentSidMap: Record<string, string | undefined> = {
  order_confirmation: process.env.WA_CONTENT_SID_ORDER_CONFIRMATION,
  order_accepted:     process.env.WA_CONTENT_SID_ORDER_ACCEPTED,
  order_dispatched:   process.env.WA_CONTENT_SID_ORDER_DISPATCHED,
  delivery_confirmed: process.env.WA_CONTENT_SID_DELIVERY_CONFIRMED,
}

async send(to: string, key: string, data: Record<string, any>) {
  const contentSid = this.contentSidMap[key]
  if (!contentSid) {
    this.logger.warn(
      `[WhatsApp] No Content SID configured for template '${key}'. ` +
      'Message not sent. Add WA_CONTENT_SID_* to deployment secrets.'
    )
    return { stub: true, reason: 'no_content_sid' }
  }
  // ... existing send logic with contentSid ...
}

STEP 3 — Add Content SIDs to .env.example
File: .env.example

Add under WhatsApp section:
  # WhatsApp Content SIDs (from Meta Business Manager → Message Templates)
  WA_CONTENT_SID_ORDER_CONFIRMATION=HXxx...
  WA_CONTENT_SID_ORDER_ACCEPTED=HXxx...
  WA_CONTENT_SID_ORDER_DISPATCHED=HXxx...
  WA_CONTENT_SID_DELIVERY_CONFIRMED=HXxx...

STEP 4 — Add to /healthz
In the notification checks block, add:

whatsappContentSids: {
  order_confirmation: !!process.env.WA_CONTENT_SID_ORDER_CONFIRMATION,
  order_accepted:     !!process.env.WA_CONTENT_SID_ORDER_ACCEPTED,
  order_dispatched:   !!process.env.WA_CONTENT_SID_ORDER_DISPATCHED,
  delivery_confirmed: !!process.env.WA_CONTENT_SID_DELIVERY_CONFIRMED,
}

This makes it immediately visible in the health check whether
WhatsApp is actually configured or silently stubbing.
